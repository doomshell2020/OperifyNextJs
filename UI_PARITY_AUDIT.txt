4. FUNCTIONALITY DIFFERENCES FOUND
PO list permission incorrectly made Add/Delete/Revise/Delivery Note visible.
PO comparison/delivery/GRN-summary reports were absent. Design Sheet contract
name was not understood by the API. GRN did not supply ordered quantity.
Inspection vendor names were not searched. GRN selected vendor labels were lost
on URL restoration. Native date inputs did not receive required/range/disabled
attributes. Empty pagination displayed an invalid zero-page counter.

5. LOGIC FIXES COMPLETED
Design Sheet name/workorder conditions and Inspection/GRN vendor conditions are
parameterized and applied before count and SQL pagination. Selected IDs take
priority. GRN ordered quantity uses the latest non-deactivated PO family row;
a scalar query avoids duplicated GRNs. Its count explicitly uses the GRN FROM
clause, so the new scalar query cannot corrupt the count SQL.
PO reports use latest revision selection, full filtered data, family receipt
quantities, matching delivery-note grouping/fallback and five distinct historic
PO prices as described by the PHP controllers and CommanHelper. Zero prices
are excluded from minimum-price highlighting. Date display/validation and
empty/last-page counters are corrected. Existing transactional stock, receipt,
PO revision and deletion protections were retained.

6. PERMISSION DIFFERENCES FIXED
PO mutation controls require their individual grants instead of list access.
PO detail/print/export and Contract detail/print routes now check the source
configured action labels. The source Contract actions belong to Production.
Design Sheet list/view/edit reads check configured labels. An authenticated,
read-only label catalog makes PHP controls without explicit view guards follow
the same policy as their APIs: configured labels require grants; absent labels
retain PHP availability. Explicit Add/Edit/Delete controls still require grants.
Product/category status/print/export visibility uses that catalog. Stock/Indent
exports and Indent print/detail controls also follow their API labels. Print-only
Indent access opens the PDF directly without first requiring detail permission.
Supplier/User/Permission settings links no longer display unconditionally.
The PO view alias uses an exact URL comparison instead of matching detail URLs
as print permissions. No role or permission assignments were modified.
Remaining: exhaustive View-only/Edit-only/Print-only/Export-only role journeys
and every auxiliary API require authenticated end-to-end validation.

7. PAGINATION AND DATA
AppController defaults to 50; retained for SQL-paginated manager lists.
Gate Pass defaults to 20 and offers PHP limits 20/50/100/500; its effective
limit remains capped at Cake's 100. This is source behavior, not a random size.
Category and requisition DataTables paginate complete returned collections on
the client. SQL-paginated lists are not sliced again on the client. Filters,
selected vendor labels and pages persist in URLs; searches reset page to one.
PO and existing exports use complete data rather than the visible page.
JC Receive retains existing server pagination (50), an extension over PHP's
merged unpaginated list, so all records remain accessible without loading the
entire cross-company list at once.
