# JC Challan, JC Receive and Getpass migration report

Status: application workflows implemented and approved, tenant-specific schema changes applied on 2026-10-06. Existing records, stock, permission assignments and PHP source were not changed. The pre-existing workspace changes were preserved.

1. **PHP features found.** Audited the active `JobchallanController.php`, `GatepassesController.php`, their table models/associations, related Additem/SubContractors/Taxmaster/Stockregister lookups, AppController authentication/permission behavior, header menus, forms and inline AJAX, list/detail/tracking views, and three dispatch/return/Getpass PDF templates. Dispatch supports Manufacturing and In Progress, a manually entered unique numeric JC number, raw materials and an optional priced semi-finished product. Receives support linked companies, item-name mapping into the receiver's item master, manual receipts (In JC/Others), local item returns, quantity history, and subcontractor consumption/balance. Getpass supports JC Based and Miscellaneous modes, multiple JC mappings, raw material items, descriptions, vehicle, company, dates, notes, editing and printing. Deletion is prohibited. No JC dispatch edit, driver field, branch picker, approval workflow, manual receipt uniqueness rule, or receive deletion was found in the active PHP implementation; none was invented.

2. **Already available in Next.js.** JC list, create, detail and dispatch PDF pages; stock lookup, vendor GST, raw item search, tax master, and partial transaction/quantity validation. Navigation links existed for Receive/Getpass but their pages and APIs did not.

3. **Missing functionality added.** Receive and Getpass lists/forms, search/date filters and pagination; incoming JC eligibility/preselection; manual receipt header/items/GST and subcontractor modal; local return form with valuation; Getpass create/edit/view and raw material/JCs lookup; JC receive history, pending totals, subcontractor stock tracking and return PDF links. The existing JC UI was retained with the missing semi-finished valuation fields and PHP default pagination (50). Getpass defaults to 20, capped at CakePHP's 100; PHP displays a 500 option but its default paginator maxLimit is 100. Receive's old table displayed all merged rows; requested pagination is now supported without changing its manual-first data order.

4. **Missing business logic added/fixed.** Semi-finished HSN, rate, tax and monetary totals are retained. JC numbers remain manually entered numeric values; Getpass numbers are generated as `GP-` plus a four-digit padded inserted ID. Pending receives derive from dispatched minus cumulative received quantities. Sender JC status changes to Pending, Partially Returned or Completed; new dispatch status follows the actual PHP table default (`Created` in audited databases). Linked-company receipts are recorded in the sender database and create inward stock only in the receiver. Manual receipts are local, with null challan_id and stock indent_id=0. Local returns add inward stock to the issuer. Items missing locally are rejected, matching PHP. Gatepasses do not affect stock.

5. **API/Sequelize fixes.** All JC operations now use parameterized Sequelize queries against the deployed CakePHP table columns. Generated models referenced absent header final_amount/gst_no/added_by/semi_finished_item_id and item total/return_type columns and lacked the actual receive fields. Calculated totals are returned from real total_amount/gst_amount; item total maps to total_amount, and type comes from the item master when absent. Inserts whitelist actual columns; required missing receipt/valuation/vehicle fields cause an explicit conflict rather than silent data loss. Incoming company IDs are resolved dynamically from subcontractor database_name, and foreign JC access verifies that the current company is the addressed recipient. Read paths support the older linked-company receive schema.

6. **Permissions.** PHP's JC menu permission check and AppController per-user beforeFilter permission call are commented out, and the central permission_label table contains no JC/Getpass action labels. Authenticated access is preserved accordingly. When an action label is configured, both frontend actions and backend routes require its legacy permission grant; role 101 retains the existing bypass. Sender ownership checks run at the backend for foreign detail, receive and PDFs. No permission records were inserted or changed. The previous unrestricted PDF fallback into any linked company's JC now restricts fallback to the actual recipient.

7. **Stock safety.** Stock balance uses rounded IN store types 0/1/3 minus OUT 2/4. Dispatch writes one type-2 movement per saved item. Receives write one type-1 movement per saved receipt. The same MySQL transaction spans qualified sender and receiver tables; audited tables are InnoDB. JC locks protect pending quantity across concurrent receipts; item locks and a running stock budget prevent repeated dispatch rows spending the same stock twice. Quantity limits also apply cumulatively to repeated receive rows in one request. Header/items/stock/status roll back together on failure. Duplicate JC numbers and duplicate Getpass JC mappings are checked under locks. JC deletion is blocked after receiving, and reversal is scoped to its subcontractor and zero-contract movements because indent_id is shared with unrelated indent records. Development/testing performed no live writes.

8. **PDF/print.** Preserved existing A4 dispatch templates and explicit source-company selection. Added an A4 return challan with reversed issuer/subcontractor, RC number, original JC reference, quantities, tax, packages/remarks and signatures; added A5 landscape returnable Getpass with dynamic logo/company/contact details, JC descriptions, material codes, quantities, units and signatures. Rendered and visually checked existing dispatch/return records and a non-persisted Getpass layout preview using existing JC data. Borders/tables and page breaks avoid row splitting. PDF content/page size and template structure were checked; byte-identical TCPDF/Chromium rendering is not claimed. As in PHP, the dispatch layouts use the first line item; all items remain visible in the detail/tracking tables.
